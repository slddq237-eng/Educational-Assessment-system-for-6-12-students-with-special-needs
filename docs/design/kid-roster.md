# 學生名單管理設計（2026-10-31）

維護者 2026-10-31 提出、和 Claude 討論後定案：學生代號改成系統自動生成、封存、刪除、重置貼紙。分五個 PR 做，每個 PR 一個分支。
路線圖在 `roadmap.md` 的 B11；程式在 `tools/literacy/setup.js`（學生名單畫面）、`data.js`（`kids`）、`shared/rewards.js`（貼紙收藏）。

## 要解決的問題

- 老師在學生名單把名字從「小明」改成「小華」、代號不變，系統當成同一位學生，小明的作答紀錄和貼紙變成小華的。
- 刪除學生只刪名單那一列，貼紙、作答紀錄、分組、各課個別教學日期都留著，變成沒人認領的殘留資料。
- 每學期學生會有變動（轉出、不再上課），名單越來越長，遊玩頁、分析頁都擠進不上課的人。

## 已定案的做法

| 項目 | 決定 |
|---|---|
| 代號 | 新增學生時**系統自動生成隨機碼**，老師不用也不能自己打（兩台電腦各自產生也幾乎不會撞，備份還原、平板紀錄匯入合併時不會搞混）。既有學生的代號（例如 `S01`）不動 |
| 代號對照表 | 放在**進階設定**「學生隨機碼對照表」，要點開才看得到，不在一開始的畫面顯示；匯出的 Excel 和平板表單仍然只有代號、沒有名字（隱私設計不變） |
| 第一次打開 | **名單是空的**，不再放範例的 S01、S02（2026-10-31 維護者決定）：選學生那一步顯示「還沒有學生，請先新增學生」和按鈕，直接打開學生名單。已經在用的人名單照舊，不自動刪除。考慮過「預設兩位隨機碼學生再提醒改名」，沒採用：換電腦還原備份時會多出兩位沒人認領的學生、沒改名的學生會在畫面上顯示隨機碼 |
| 名字不能重複 | **學生名字一定要不同**（現在名單和封存區一起算，2026-10-31 維護者決定，取代「同名時提醒」）：新增、改名遇到重複就擋下並請老師換名字；取消封存時如果現在名單已有同名的，也擋下、請先改名；以前留下的重複名字在名單上標紅提醒。備份還原、匯入帶進來的重複名字擋不了，名單照樣標紅，`kidLabel` 遇到同名會加代號分辨 |
| 改名字 | 可以改，**改之前提醒**：「改名後評量紀錄會沿用；要新增學生才會是不同的學生」 |
| 封存 | 單一學生可封存：移到「封存區」，作答紀錄、貼紙、頭像都不動，遊玩頁、分析頁（包括全班統計）、平板作答都不顯示。要查看就在封存區「取消封存」，取消時請老師**確認年級**（年級是用學年自動算的，隔很久才回來會一次補算好幾年，沒有留級的處理）。封存時不從分組拿掉，取消封存後分組自動回來 |
| 刪除 | 單一學生可刪除：連同貼紙、作答紀錄、分組、各課個別設定**全部刪掉**，救不回來；確認視窗建議老師改用封存、並提醒先下載備份 |
| 匯入規則 | 平板紀錄匯入時，**名單裡沒有的代號先提醒、不收進來**（以前是照樣匯入並補發貼紙）；封存學生的代號算「名單裡有」，資料照收但仍然隱藏 |
| 重置全部貼紙 | 老師專用按鈕＋確認視窗；**記下重置時間，重置前的舊平板紀錄匯入時不再補發貼紙**；作答紀錄本身不動 |
| 新學期「整理名單」提醒 | 換學期後第一次打開學生名單時提醒；列出**上一學期完全沒有作答紀錄的學生**，預設不勾選、由老師勾選後一次封存；系統不自動封存任何人 |

封存的做法：把封存學生從現在名單移到另一份封存名單（約 38 處用到名單的畫面自動看不到他們），不改作答紀錄格式。

## 已知的限制（不在這次範圍）

- **同一位學生重學同一課，教學日期只能存一組**（2026-10-31 查程式發現）：教學日期依「課」存、一位學生一課只有一組開始日和結束日，不分學期。例如四年級原班學過第 3 課，五年級在學習扶助重學同一課，新日期會蓋掉舊日期。作答紀錄本身有各自的時間，不會壞；影響的是圖表橫軸的教學期間和「教學後天數」。要修就要碰分析邏輯，記在 `pending.md`，先討論。
- 年級自動升的規則：每年 8 月起學年加 1，年級自動加 1，最高六年級；舊紀錄保留作答當時的年級。
