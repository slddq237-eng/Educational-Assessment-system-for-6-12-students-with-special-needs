# 部件三層設計（2026-10-31 維護者提出，討論稿）

部件（字拆成的小塊，例如「清」＝氵＋青）以後會被六個功能讀取。這份把「部件分幾層」「每個功能讀哪一層」「新玩法怎麼用部件」寫在一起。
**目前狀態**：設計討論稿，程式還沒改；現況（平台現在怎麼讀）見 `docs/materials/materials.md`「部件資料的狀況」。新玩法 R5、R6、W3 的舊設計與待解決問題見 `literacy-play.md`「聽音補部件、聽音選部件」，這份定案後會回頭改寫那一節。

## 1. 三層定義

| 層 | 內容 | 和現在的對照 |
|---|---|---|
| 第一層 | 按結構拆成 **2～3 個可讀出聲音的部件**（例如「清」＝氵＋青；「森」＝木＋木＋木） | 取代現在的 A 欄「形符＋聲符」；**不再標形符、聲符**，A 欄的讀音比對改成只用來檢查「可讀出聲音」 |
| 第二層 | **可教學角度拆到最細**：拆到部首就停，不拆成單一筆畫或罕用字；同一部件出現幾次寫幾次 | 就是現在的 B 欄 |
| 第三層 | **開源部件（cjkvi-ids）拆到最細，只存最底層**：拼起來剛好是字，不含中間層 | 現在的「拆到最細（電腦，含中間層）」；備課分析要的「含中間層」由程式用 `prep.js` 的 `allParts` 遞迴算，不存進表格 |

規則：
- **可讀出聲音**：部件是一個字，或是部首的變體。變體對照到原來的字：氵→水、扌→手、艹→草、亻→人、忄→心、犭→犬、礻→示、衤→衣、糹→糸、釒→金、⺮→竹、灬→火、刂→刀；阝要看位置（左＝阜、右＝邑）；辶、攵、廴等其他變體之後補全，請老師確認。**遊戲不會唸出部件的讀音**，這只是產生第一層資料時的標準。
- **每層各有「電腦」和「人工手動」兩欄**（第三層只有電腦）。讀取時每層都是「人工手動 → 電腦」；老師還沒確認的電腦拆法照樣算有資料。
- **「沒有」的意思**：該層完全沒資料（例如獨體字、拆不出來）才往下一層；三層都沒有就當獨體字，照舊用切塊提示（見 `literacy-play.md` 的 `cutHtml`）。
- **足、酋不再往下拆**（2026-10-29 維護者決定）：每一層都當成一整塊。
- 人工手動欄寫「待討論」的格子標紅色、不寫進平台；表格另加「狀態」欄（已確認／待確認／待討論），不要只靠顏色。
- **舊的 `PARTS`（康軒四上 86 字人工部件）**先歸到第二層人工手動欄，狀態標「待確認」，請老師之後確認；`PARTS` 這個資料就退場，讀取統一走各層。部分字（例如串＝口 口 丨含單一筆畫）不符合第二層規則，確認時一併改。

## 2. 每個功能從哪一層開始讀

統一規則：每個功能只指定「**起點層**」，該層沒有資料就往下一層讀。

| 功能 | 起點層 |
|---|---|
| (1) 各評量的部件提示 | 第二層 → 第三層 |
| (2) 備課分析 | 老師自己選第一層／第二層／第三層（單選；複選會讓同一個字重複計入排行） |
| (3) 部件重組（R4） | 第二層 → 第三層 |
| (4) 聽音選部件 | 第二層 → 第三層 |
| (5) 聽音補部件（R5） | 第一層 → 第二層 → 第三層 |
| (6) 看部件寫字（W3） | 第一層 → 第二層 → 第三層 |

為什麼 (5)(6) 從第一層：這兩個要「遮住一塊部件」，第一層是 2～3 塊、位置單純；第二層以後常有部件包在別的部件裡面，位置不好對。
(1)(3) 現在讀的是 B（＝第二層），所以這兩項改完後畫面幾乎不變，老師已填的 23 個 B 人工手動（南一六上）照樣用到。

## 3. 三個新玩法

1. **聽音選部件**（R6；2026-10-31 維護者決定從「聽音拼部件」改名）：聽字音，從選項挑出組成這個字的部件（複選）。**全部選對才算對**（2026-10-31 維護者決定）；點選項第一次＝選取、第二次＝取消選取，學生選錯可以改。**重複部件拆出幾個就算幾個答案**：森拆出三個木，答案就是三個木（選項裡要有三張一樣的木卡；4 塊的字例如擤，答案 4 張、至少再加 2 張干擾；干擾部件不能和答案部件相同，2026-10-31 維護者確認）。**紀錄只記最後送出的選擇**，不記選取、取消的過程（2026-10-31 維護者決定）。選項**固定至少 6 個**，需要一個「部件選項池」挑干擾部件（形近部件優先，見 `literacy-play.md` 待解決問題 3、4）。
2. **聽音補部件**（R5）：上方顯示這個字，**遮住一塊部件**（練習隨機遮；正式評量固定，見下），其餘部件看得到；學生從 **4 個選項**（1 個答案＋3 個干擾部件）選出被遮的那一塊。兩部件的字遮一塊、露一塊；三部件的字遮一塊、露兩塊。
3. **看部件寫字**（W3）：同樣顯示遮住一塊部件的字（遮法同聽音補部件），學生寫出來。**一律不做錯誤分析、不記錄對錯**，只留「這個字練習過」的練習紀錄（2026-10-31 維護者決定）。

### 遮哪一塊

- **練習**：每題隨機遮一塊（2026-10-31 維護者決定）。
- **正式評量**：每個字固定遮同一塊，評量條件才固定（2026-10-31 維護者決定）。非包圍的字照**筆順的先後順序**，遮**比較晚寫到的部件**；**包圍結構的字不管筆順，一律遮被包圍的裡面**（2026-10-31 維護者決定，這樣外層的 L 形、口字形不用遮，也不用逐字查包圍字的筆順）。三塊的字遮最晚寫的那一塊。

| 第一層結構 | 遮的部件 |
|---|---|
| 左右、左中右 | 右邊那塊（筆順先左後右） |
| 上下、上中下 | 下面那塊（筆順先上後下） |
| 左上、左下、右上、上方、下方、左方、全包圍（例：病、道、句、問、凶、區、國） | **裡面（被包圍）的那塊**，不看筆順 |
| 交疊、獨體字 | 還沒訂，第一版略過 |

- 筆順核對（2026-10-31 對照教育部國字標準字體筆順學習網，看筆順圖）：左右、上下類照筆順就是遮右邊、下面；包圍類原本想照筆順遮，但發現外層不一定先寫（辶、廴、區的匸、凶的凵、國的囗封口都最後寫），所以改成一律遮裡面。**只抽查了幾十個字，左右、上下、左中右、上中下的個別例外還要老師確認。**
- 程式不算筆順，**每個字的「正式評量遮哪一塊」存在資料裡**：先照上表自動填，老師可以在人工手動欄改；實作時放進部件表（步驟 2）。
- 這也算正式評量條件，R5、R6、W3 開放正式評量時要記進 `a3-conditions.md`。

### 遮蔽怎麼做

- 遮蔽要知道部件在字的哪裡，所以**平台要有每個字第一層的「結構」**（左右、上下…）。目前結構只在部件表 Excel 的「結構」欄，網頁讀不到，要隨資料步驟一起寫進 `shared/`。
- 先用 CSS 在字上蓋一塊區域，**不另外做圖檔**；先挑 5～10 個字做原型，確認全字庫正楷體畫出來的位置準不準，再決定要不要改用圖檔。
- 第一層是左右、上下、左中右、上中下的字，用長方形遮得住：2026-10-31 的部件表 2,160 字裡約 1,830 字（85%）。
- 第一層**本身**就是包圍結構的字約 222 字（11%），例如道＝辶＋首、國＝囗＋或：因為只遮**裡面**，也是一塊長方形，不用做 L 形：每種包圍結構訂一個預設位置（左上包圍的裡面在右下、左下包圍的在右上、右上包圍的在左下、上方包圍的在下方偏中間、下方包圍的在上方偏中間、左方包圍的在右邊偏中間、全包圍的在中間），個別字不準再微調。部件資料的順序要「外層在前、裡面在後」（和 cjkvi-ids 一致），老師填人工手動欄時也要照這個順序。「艇」第一層是舟＋廷（左右），不屬於包圍。
- 交疊（20 字）、獨體字（86 字）略過。退到第二層也不會讓包圍字好遮（第二層的部件位置更複雜），所以遮蔽題**不退到第二層**。

## 4. 這些改動不會碰到的事

- 第 1～3 步（本檔、部件表和資料改版、統一讀取規則）**不動作答紀錄格式、不動正式評量條件**。
- 新玩法（第 4 步）要新增評量目標和欄位，屬於「改作答紀錄格式」，**開工前先討論**（`a8-terms.md` 第 24 點：E4 開工時再加欄位，只加不升版）。

## 5. 資料與程式介面（讓之後其他程式也好讀、符合整理程式的規則）

目標：以後任何工具要用部件，都只**呼叫一個入口**，不用知道資料放哪幾個檔、人工和電腦怎麼挑。對應 `docs/code/refactor.md` 規則 1（一律走入口）、規則 2（共用程式包成一個盒子）、規則 3（整理和新功能分開）。

1. **一個資料檔**：新增 `shared/parts-layers.js`，**由 `make_parts_columns.py` 自動產生、不手改**（來源是部件表 Excel 的人工手動欄加 cjkvi-ids）。每個字存：結構、第一～第三層的電腦拆法、老師的人工手動拆法、每層的狀態（已確認／待確認／待討論）、正式評量遮哪一塊。
   - 不放進 `shared/lessons.js`（約 86 KB，混著各本課本的字、語詞，改版號和課本資料時容易衝突；現在用正規表示式改寫裡面的 `PARTS_A`、`PARTS_B` 兩行也很脆弱）。**這修正了我先前「結構表放 `lessons.js`」的建議**，請你確認。
   - 舊的 `PARTS`（康軒四上 86 字）、`PARTS_A`、`PARTS_B` 都併進這個檔，`parts.js` 的 `PARTS_AUTO` 先留著當第三層的原料，之後再看要不要併。
   - 大小我用現在部件表估過：2,160 字約 100 KB 上下（壓縮後約 25 KB），和 `parts.js`（約 45 KB）同等級；獨立一個檔，不需要部件的頁面可以不載入。
2. **一個入口 `window.Parts`**（新的共用盒子，檔案開頭有中文說明）：
   - `Parts.read(字, {from: 起點層})`：回傳 `{層, 部件, 來源（人工／電腦）, 狀態}`，從起點層開始、每層「人工 → 電腦」、沒有就往下一層。
   - `Parts.layer(字, 第幾層)`：只看某一層（備課分析用）。
   - `Parts.struct(字)`：結構；`Parts.mask(字)`：正式評量遮哪一塊（練習的隨機由玩法自己抽）。
   - `common.js` 現在的 `rawParts`、`partsSource`、`KEEP_WHOLE` 等先變成呼叫 `Parts` 的薄包裝，各檔案改完再移除。
3. **自動檢查加一條規則**（像存資料的 `STORAGE_ENTRY`）：只有 `parts-layers.js` 和 `Parts` 盒子可以直接讀 `PARTS`、`PARTS_AUTO`、`PARTS_A`、`PARTS_B`，其他檔案直接讀會報錯誤。
4. **文件**：`architecture.md` 加這個檔案和入口；`materials.md` 部件資料的狀況改寫現況。
5. 這些都不改作答紀錄格式；紀錄記的是字本身，部件拆法改了不影響舊紀錄。

## 7. 已決定的做法與還要老師確認的事

**已決定**（2026-10-31 維護者同意我的建議）：
- **筆順資料不放進 repo**，只當人工核對的參考（授權限制見第 3 節的筆順核對說明）；之後要自動產生遮擋資料再請維護者和智財單位確認。
- **部件選項池**：第一版自動算（共用一塊、換掉另一塊的形近字，例如柱→桂，干擾部件是圭），排除單筆畫；算不出來的字用同課其他字的同層部件補；**形近部件表先不做**，等有題目品質回饋再決定。
- **看部件寫字不做錯誤分析、不記對錯**，只留練習紀錄。這和路線圖 E3 寫的「書寫由老師評分」要對一下，E3 開工時改寫那一列。

**要老師確認**（步驟 2 做資料時一起做）：
- **筆順例外**：左右、上下、左中右、上中下裡不是「先左後右、先上後下」的個別字，我列候選請老師對照筆順網；沒確認的字先用預設並標「待確認」。包圍字不看筆順，不用確認。
- **部首變體對照表**：我先列部件表裡實際出現的部首變體（氵→水…），阝要看位置（左阜、右邑），請老師確認。
