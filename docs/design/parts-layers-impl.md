## 1. 資料與程式介面（讓之後其他程式也好讀、符合整理程式的規則）

目標：以後任何工具要用部件，都只**呼叫一個入口**，不用知道資料放哪幾個檔、人工和電腦怎麼挑。對應 `docs/code/refactor.md` 規則 1（一律走入口）、規則 2（共用程式包成一個盒子）、規則 3（整理和新功能分開）。

1. **一個資料檔**：新增 `shared/parts-layers.js`，**由 `make_parts_columns.py` 自動產生、不手改**（來源是部件表 Excel 的人工手動欄加 cjkvi-ids）。每個字存：結構、第一、第二層的電腦拆法、老師的人工手動拆法、每層的狀態（已確認／待確認／待討論）、正式評量遮哪一塊；**第三層不存**（2026-10-31 步驟 3b 決定：存了會讓識字評量頁面超過 1 MB 的下載量提醒線，改由 `Parts` 從 `parts.js` 一路往下拆算出來，產生資料時會檢查兩邊一致）。
   - 不放進 `shared/lessons.js`（約 86 KB，混著各本課本的字、語詞，改版號和課本資料時容易衝突；現在用正規表示式改寫裡面的 `PARTS_A`、`PARTS_B` 兩行也很脆弱）。**這修正了先前「結構表放 `lessons.js`」的建議，2026-10-31 維護者確認改放新檔。**
   - 舊的 `PARTS`（康軒四上 86 字）、`PARTS_A`、`PARTS_B` 都併進這個檔（第二層人工手動），`lessons.js` 裡這三個資料 2026-10-31 步驟 3b 已拿掉；`parts.js` 的 `PARTS_AUTO` 留著當第三層的原料。
   - 大小（2026-10-31 實際產生）：存第三層時約 210 KB（壓縮後約 40 KB），不存第三層約 147 KB（壓縮後約 27 KB）；`parts.js` 約 45 KB（壓縮後約 19 KB）。先前我曾把約 210 KB 誤報成約 100 KB，已更正。獨立一個檔，不需要部件的頁面可以不載入。
2. **一個入口 `window.Parts`**（新的共用盒子，檔案開頭有中文說明）：
   - `Parts.read(字, {from: 起點層})`：回傳 `{層, 部件, 來源（人工／電腦）, 狀態}`，從起點層開始、每層「人工 → 電腦」、沒有就往下一層。
   - `Parts.layer(字, 第幾層)`：只看某一層（備課分析用）。
   - `Parts.struct(字)`：結構；`Parts.mask(字)`：正式評量遮哪一塊（練習的隨機由玩法自己抽）。
   - `common.js` 原本的 `rawParts`、`partsSource`、`KEEP_WHOLE` 等已搬進 `parts-api.js`（2026-10-31 步驟 3a）；因為只有識字評量 `data.js` 和備課分析 `prep.js` 兩處在用，直接改成呼叫 `Parts.compat`，沒有另外留包裝。
3. **自動檢查加一條規則**（像存資料的 `STORAGE_ENTRY`）：只有 `parts-layers.js` 和 `Parts` 盒子可以直接讀 `PARTS`、`PARTS_AUTO`、`PARTS_A`、`PARTS_B`，其他檔案直接讀會報錯誤。
4. **文件**：`architecture.md` 加這個檔案和入口；`materials.md` 部件資料的狀況改寫現況。
5. 這些都不改作答紀錄格式；紀錄記的是字本身，部件拆法改了不影響舊紀錄。

## 3. 獨體字與沒有第一層的字（2026-10-31 維護者決定）

- **部件相關的玩法不出獨體字**：部件重組（R4）、聽音補部件（R5）、聽音選部件（R6）、看部件寫字（W3）問的是「哪一塊部件」，獨體字沒有部件，所以不出題。部件重組原本對獨體字用「切塊」出題，2026-10-31 步驟 3c 起不出（`data.js` 的 `goalSkips`）。
- **部件提示（輔助，不算評量題目）**：獨體字改成**黑圓圈遮住字的中心、只露出旁邊的樣子**，取代以前打亂旋轉的切塊（2026-10-31 步驟 3c 已做）。圓圈直徑約字寬的 0.6 倍（維護者 2026-10-31 指定，CSS `.holech::after` 的 `.5em`）；我用全字庫正楷體畫出 111 個拆不開的字量過：蓋住中心後剩下的筆畫不到四成五的 25 個字，加上「人」，共 32 個字不給這種提示（`data.js` 的 `HOLE_SKIP`：本申入十未曳巾牛身華東事舟井八及畢才年一革乍末手專人口日白自米心；名單是看截圖挑的，還沒逐字檢查完），系統自動跳到下一個提示。
- **遮擋題只對照第一層，不退到第二層**：沒有第一層的字不出遮擋題。2026-10-31 資料：獨體字 88 字；非獨體字但第一層拆不出來 214 字（143 字資料裡最上層有一塊對不到字、70 字有部件讀不出聲音、1 字是足）；加上交疊結構，遮擋題大約少 319 字。**這些字請老師補「第一層（人工手動）」**：70 字讀不出聲音的先到「部首變體對照」頁補，143 字要人工填。
- **設定畫面一定要顯示「這個目標有 N 字不出題」**，不能悄悄少題（`docs/code/refactor.md` 規則 8）；`data.js` 現在就有算每課「拆得開的字數」，可以沿用。

## 4. 待決

- **拆不開的字能不能用圖檔遮蔽**（2026-10-31 維護者提問：Claude 用圖形檔遮蔽，或維護者上傳遮好的圖檔當資料）：
  - 建議**第一版用「遮蔽區域的數字」**（每字存幾個數字，例如遮右下角、占 40%×50%，網頁用 CSS 或 SVG 蓋在字上），不用圖檔：資料量小、字型和畫面一致、放大不糊、平板不用另外下載、不會有新的圖片授權問題；這本來就是步驟 4d「個別字遮蔽位置微調」要做的事。
  - **圖檔只留給數字做不到的字**，例如交疊結構的字（約 20 字，部件在空間上重疊，長方形蓋不住）。
  - 若提供圖檔：每張要對應「哪個字、遮住哪一塊部件」（選項要用部件出）；格式建議 SVG 或 PNG，一字一張「遮好的」；少量直接貼在對話，大量傳進 repo 的資料夾再登記；Claude 也可以用 repo 的楷體字型畫字加遮罩，再由維護者或老師確認遮哪一塊。
  - **法律**：圖不能是從出版社課本或教育部筆順網截圖的（課本有著作權；筆順網是非商業、禁止改作）；用楷體字型自己畫的，要先核對字型（全字庫正楷體）的授權允許轉成圖片；有新的圖片資料要更新 `docs/materials/data-sources.md` 和 `about.html`。
  - **什麼時候決定**：步驟 4b（聽音補部件）先用數字做原型，看哪些字做不到，再決定要不要圖檔。
