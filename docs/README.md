## 2. 合作規則（詳細版；CLAUDE.md 只放一定要做的事）

- 分資料夾負責；`shared/`、首頁 `index.html`、`privacy.html`、`README.md`、`CLAUDE.md`、`docs/` 是共用檔案，改前提醒維護者告知夥伴，PR 說明要標出。
- 開工前到 GitHub 的 Pull requests 檢查是否有未合併的 PR 動到同一批檔案（Files changed）；有的話先說好誰先改。
- 開工就先發草稿 PR（2026-10-20 維護者決定），讓 PR 清單成為「誰正在改哪裡」的即時看板；做完再改成可合併。人多了之後（3～5 人）再加 GitHub Projects 看板與 CODEOWNERS，更多人時加 GitHub Actions 自動提醒同檔案衝突（規格書「合作規則」、待決問題 H 類）。
- 新功能開分支、發 PR；不直接推 main。**合併分級**（2026-10-22 維護者決定）：動到共用檔案（`shared/`、`docs/`、首頁、`privacy.html`、`CLAUDE.md`、`README.md`、`.github/`）、識字評量 `tools/literacy/`、作答紀錄格式或正式評量條件的，要 repo 擁有者（slddq237-eng）同意才合併，Claude 不自己合併；只改自己新工具資料夾 `tools/<工具名稱>/` 的，自動檢查通過後作者可以自己合併，合併後告知擁有者（首頁加入口那段仍要同意）。
- **文件同步分級**（2026-10-22 維護者決定）：新想法、老師回饋、做了決定都要記進本文件和規格書；新功能或改變行為的改動在同一個 PR 更新本文件，影響設計時才更新規格書（定期整批同步，見「規格書怎麼跟上」）；修 bug、改錯字、小調整不用記。
- 純前端、無建置工具。repo 公開：嚴禁把學生姓名、照片、成績寫進任何檔案。
- **自動檢查**（2026-10-22 加）：每次發 PR、改 main，GitHub Actions 會跑 `docs/scripts/check.js`（設定檔 `.github/workflows/check.yml`），檢查程式語法、教材資料（語詞裡有沒有這個字、干擾字有沒有包含答案等）、各頁版本號是否一致、有沒有照片或備份檔等學生資料。PR 頁面出現紅叉就先修好再合併；本機可以跑 `node docs/scripts/check.js`。已知、等決定的教材問題放在檔案裡的 `KNOWN`（只提醒不失敗）。建議 repo 擁有者在 Settings → Rules 設定「main 要檢查通過才能合併」。
- 維護者是新手：回覆用繁體中文，術語附白話解釋；程式碼每個段落開頭加中文說明（不逐行註解）。
- **檔案放哪裡**：每個小工具放 `tools/<工具名稱>/`，入口是該資料夾的 `index.html`，首頁 `index.html` 列出工具。教材資料只放 `shared/lessons.js`、工具間共用的小工具只寫在 `shared/common.js`，不要在工具資料夾另外複製一份。各檔案的關係見 `architecture.md`。
- **教材與字型**：新增課本後執行 `docs/scripts/make_parts.py`、`make_bpmf.py`、`make_kai.py`（改了頁面文字也要跑 `make_kai.py`）；讀音、注音以課本為主（見 `materials.md`）；楷書一律用 `TWKai`（全字庫正楷體），不要用霞鶩文楷或 Kaiti TC 等大陸字形的楷體。維護者上傳教材檔案時，先說哪些讀得到、哪些讀不到和解決方法（見 `data-sources.md`「上傳教材檔案、課本改版時」），原檔不放進 repo。
- **省 token**（2026-10-23 維護者決定）：`CLAUDE.md` 每則訊息都會載入，只寫一定要做的事、指回這裡；詳細規則只寫在 `docs/` 一個地方（根目錄 `README.md` 和規格書只放摘要或連結）。大檔案不整份讀，先搜尋再讀需要的段落。給人看的使用建議：claude.ai 文件「省 token 的 Claude 使用指南」（https://claude.ai/artifact/2DSYrCEwmkGVrqNpHRTTEG，需擁有者分享）。

### 三級通知與每週摘要（2026-10-22 維護者決定）
兩位維護者都忙，不可能每個改動都等對方同意；但自己做（就算和 Claude 討論過）也可能做錯。所以依「做錯的代價」分三級：

| 等級 | 哪些改動 | 夥伴要做什麼 | 例子 |
|---|---|---|---|
| ① 先討論再做 | 會寫進作答紀錄、改正式評量條件、法律與授權 | 事前一起決定（整理成選項，夥伴只要選） | A8 名詞與時期、A3、例句版權、LICENSE |
| ② 做完讓他知道 | 新功能、改畫面、改讀音或教材、改文件或合作規則 | 看每週摘要，有意見再提；不回覆就照原計畫 | 練習大勾叉、讀音照課本、文件拆分 |
| ③ 不用通知 | 修錯字、修 bug、小調整 | 不用看 | 「扇子」、「呱呱」 |

- 每個 PR 說明標「通知等級」和理由；**拿不準就升一級**。
- 會影響學生作答畫面的改動，合併後維護者自己先玩一次；第二級裡比較大的改動，可以先用草稿 PR 讓夥伴先看。
- **每週摘要**：維護者說「本週摘要」，Claude 從這週合併的 PR 整理 5～10 行白話，分兩區——「需要你的意見」（最多 3 題，附選項）、「知道就好」（可略過），每項附 PR 連結；維護者轉貼到 LINE。最後另外列出 `docs/` 裡還標「待同步規格書」的項目，提醒擁有者同步（見上方「規格書怎麼跟上」）。重要的那題在 LINE 直接點名問。
- 第二級做錯可以用一個 PR 退回；自動檢查、規格書和 `docs/` 記下的理由，是不靠夥伴也能抓錯的保險。
