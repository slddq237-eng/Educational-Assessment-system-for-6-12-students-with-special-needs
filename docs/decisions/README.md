# 決策紀錄（2026-11-02 新增）

**這裡記「當初為什麼這樣決定」**，讓以後加入的老師、工程師、AI 不用翻 git 紀錄就看得到想法怎麼變。一個決定一則短檔案，**只在做決定時寫，不是每個 PR 都寫**。

## 三種紀錄各管什麼（每件事只記一次）

| 紀錄 | 放哪裡 | 記什麼 |
|---|---|---|
| 現況 | 主題文件（`design/`、`materials/` 等） | 「現在是什麼」。改變決定時直接改寫，不讓新舊說法並存 |
| 決策紀錄 | 本資料夾 | 「為什麼這樣決定」「以前怎麼想」。只有做決定時才寫 |
| 流水帳 | PR 標題、`changelog/`（由 `changelog.js` 產生） | 「每次改了什麼」。PR 標題用一句話寫清楚 |

## 什麼時候要寫一則

- 定案、取消、改方向（包含「決定不做」）。
- 影響**作答紀錄格式、正式評量條件**（A3、A8 這類）、授權版權、合作流程的決定，一定要寫，並把完整理由放進來，**不要精簡**。

不用寫：修 bug、改錯字、一般實作細節、單純的進度更新。

## 怎麼寫

1. 檔名：`日期-英文短名.md`，例如 `2026-11-02-example-name.md`。用日期、不用流水號，兩個 PR 同時開也不會撞號。
2. 複製下面的模板，每一欄一行，欄位名稱不要改（自動檢查會看）。
3. 在本頁最下面的「索引」加一行，**最新的放最上面**。
4. 決定被推翻時：新開一則，把舊的那則「狀態」改成「已被 `○○` 取代」，舊的不刪。

```
# 一句話：決定了什麼
- 日期：2026-11-02
- 狀態：有效
- 決定：1～3 句
- 為什麼：
- 放棄的選項：（有才寫這一行）
- 以前怎麼想：一句話；沒有就寫「—」
- 影響範圍：作答紀錄／正式評量條件／畫面／教材／授權／流程（可複選）
- 來源：PR 編號、docs 檔名與節名、規格書節名
```

「狀態」只能是：`有效`、`已被 ○○ 取代`、`AI 整理，待確認`。
