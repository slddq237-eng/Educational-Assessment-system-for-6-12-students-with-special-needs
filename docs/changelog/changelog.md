# 變更紀錄（入口）

每一次 PR 改了什麼、想法或決定怎麼變，一列一筆，從舊到新排（2026-10-24 維護者要求）。用途：看出某件事每次被改動的變化流向。
現況寫在各主題文件；被拿掉的舊說法在 history 檔案；這裡只記「哪一天、哪個 PR、改了什麼、想法怎麼變」。
**平常工作不用讀這裡**（Claude 也一樣），要追某件事的變化時才讀；2026-11-02 起發 PR 不用另外寫變更紀錄（PR 標題就是紀錄，見下方「怎麼寫」），也不用讀這裡。

## 怎麼看某件事的變化

- 在 GitHub 上用瀏覽器的「尋找」（Ctrl＋F），在各分段檔案搜尋關鍵字，例如「平板」「賓果」「只考有教的字」，依時間往下看。
- 「動到哪裡」欄可以先篩出相關的工具或文件；點 PR 編號可以看當時的完整說明和改了哪幾行。
- 也可以直接請 Claude 整理：「幫我整理○○從開始到現在的變化」。

## 怎麼寫（2026-11-02 起不用再寫小檔；之前是每個 PR 一個小檔）

- **不用另外寫變更紀錄，PR 標題就是紀錄。** 標題用一句話寫清楚「改了什麼」（例如「識字評量：上下排版面的選項不再被擠小」；不要只寫「更新」「修正」這種看不出內容的字），細節寫在 PR 說明。
- 看整張表：執行 `node docs/scripts/changelog.js`（加關鍵字只印相關的列，例如 `node docs/scripts/changelog.js 平板`）。新 PR 的列由 git 的合併紀錄自動產生：PR 編號和日期取自合併紀錄、「改了什麼」是 PR 標題、「動到哪裡」依改到的檔案自動分類（換版本號會動到每個網頁，所以可能多列幾個工具，要精確請點 PR 看）。
- **想法或決定改了**：寫在對應的主題文件（見 `rules.md`「做了決定」那一列），原因寫進 PR 說明；這張表的「想法或決定的變化」欄只留給舊的列。
- 2026-10-24～2026-11-02 的 PR 各有一個小檔案（`docs/changelog/changes/`，每個檔案寫日期、動到哪裡、改了什麼，有才寫想法或決定的變化），保留原樣、照常讀進整張表，不用搬也不用改；之後不再新增。自動檢查還會提醒舊檔少了哪一欄。
- 舊的分段檔案（上表）不再加列，保留原樣。以前的寫法（在最新的分段檔案最後加一列）原文在 `history-2026-10-24.md`「變更紀錄的舊寫法」。
