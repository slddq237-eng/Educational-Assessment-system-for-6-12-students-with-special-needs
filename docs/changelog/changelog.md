# 變更紀錄（入口）

每一次 PR 改了什麼、想法或決定怎麼變，一列一筆，從舊到新排（2026-10-24 維護者要求）。用途：看出某件事每次被改動的變化流向。
現況寫在各主題文件；被拿掉的舊說法在 history 檔案；這裡只記「哪一天、哪個 PR、改了什麼、想法怎麼變」。
**平常工作不用讀這裡**（Claude 也一樣），要追某件事的變化時才讀；寫的時候在 `docs/changelog/changes/` 加一個小檔案（見下方「怎麼寫」），不用讀這裡。

## 怎麼看某件事的變化

- 在 GitHub 上用瀏覽器的「尋找」（Ctrl＋F），在各分段檔案搜尋關鍵字，例如「平板」「賓果」「只考有教的字」，依時間往下看。
- 「動到哪裡」欄可以先篩出相關的工具或文件；點 PR 編號可以看當時的完整說明和改了哪幾行。
- 也可以直接請 Claude 整理：「幫我整理○○從開始到現在的變化」。

## 怎麼寫（每個 PR 都要；2026-10-24 改成一個 PR 一個小檔）

- **發 PR 時**在 `docs/changelog/changes/` 加一個小檔案，檔名＝日期＋幾個英文字，例如 `docs/changelog/changes/2026-10-25-sticker-book.md`（用不同的名字，兩個 PR 同時開也不會衝突；不用寫 PR 編號）。內容照這個格式，每一欄一行：

  ```
  # 一句話標題
  - 日期：2026-10-25
  - 動到哪裡：識字評量、文件
  - 改了什麼：一句話就好，細節留在 PR 說明
  - 想法或決定的變化：有才寫，也是一句話（從什麼改成什麼、為什麼）；沒有就寫「—」
  ```
- **想法或決定改了、但這次沒有改檔案**（例如開會決定）：一樣加一個小檔，下一個 PR 一起帶上去。
- 看整張表：執行 `node docs/scripts/changelog.js`（加關鍵字只印相關的列，例如 `node docs/scripts/changelog.js 平板`），它會從 git 的合併紀錄找出 PR 編號，還沒合併的標「還沒合併」。自動檢查會提醒小檔案少了哪一欄。
- 舊的分段檔案（上表）不再加列，保留原樣。以前的寫法（在最新的分段檔案最後加一列）原文在 `history-2026-10-24.md`「變更紀錄的舊寫法」。
