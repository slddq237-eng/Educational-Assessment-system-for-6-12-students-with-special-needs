## 2. 合作規則（也寫在 CLAUDE.md）

- 分資料夾負責；`shared/`、首頁 `index.html`、`privacy.html`、`README.md`、`CLAUDE.md`、`docs/` 是共用檔案，改前提醒維護者告知夥伴，PR 說明要標出。

- 開工就先發草稿 PR（2026-10-20 維護者決定），讓 PR 清單成為「誰正在改哪裡」的即時看板；做完再改成可合併。人多了之後（3～5 人）再加 GitHub Projects 看板與 CODEOWNERS，更多人時加 GitHub Actions 自動提醒同檔案衝突（規格書「合作規則」、待決問題 H 類）。

- 純前端、無建置工具。repo 公開：嚴禁把學生姓名、照片、成績寫進任何檔案。
- 維護者是新手：回覆用繁體中文，術語附白話解釋；程式碼每個段落開頭加中文說明（不逐行註解）。

### 正式評量 vs 練習（兼顧遊戲性與研究嚴謹度）
- **正式評量**：條件固定（選項數、提示、答錯規則都用「評量設定」的標準），出題為**純平均隨機**，結果納入學習分析。基線期固定無提示。
- **練習**：選項數、提示、答錯規則可自由調整；平均隨機時加入 **20% 常用字**（字頻最高的字，提高動機與成功經驗），結果另外統計。
- 20% 常用字**只用在練習**：放進正式評量會墊高正確率（內容效度）並造成測驗練習效應。紀錄有「常用字加題」欄位可篩除。
- 預設題數：正式評量＝一課的量（所選版本每課生字數的平均）；練習＝**一次 10 個字**（2026-10-21 維護者決定：一課的字數每課不同，多位學生輪流會玩很久；`tools/literacy/setup.js` 的 `PRACTICE_COUNT`）。快速開始的「課堂練習」在選課次下面有兩個按鈕：「快速隨選」（預設，隨機 10 個字）「全課生字」，不到 10 個字的課直接全課生字、不顯示按鈕（`state.qCount` 為 `"all"`，換課次後仍是全部）；進階設定仍可改成一課的量、全部或自訂。
- 正式評量的出題方式固定平均隨機；常錯優先、字頻優先只開放給練習，且只有題數 ≠ 預設時才出現選項。
- 增強物（之後做）在正式評量依「完成題數」給、不論對錯；練習可依答對給。增強只出現在題目之間。

  - 正確率＝第一次就答對的比例；反應時間＝答對題的平均秒數；流暢性＝每回合第一次就答對的題數 × 60 ÷ 時限。
  - 依時間：橫軸可選測驗日期（每次評量一個點）或教學開始後第幾天（只算有教學日期的課）；時期改變處畫虛線並標時期；教學安排開始日畫直線；流暢性畫目標線。
  - 間隔分組：教學後天數（教學前或教學中／0～6／7～13／14～29／30 天以上）、距上次評量（第一次考／同一天／1～6／7～13／14～29／30 天以上）。
- 全班總表：學生 × 生字，格子是第一次就答對比例與次數，顏色只用一種藍色（越深越好）。
- 逐字學習紀錄：任何畫面點字就打開，列出那位學生那個字的每一次作答（含標註的中途結束），可匯出。
- 進階分析：1 個指標（筆數、正確率、錯誤率、答對秒數、第一次作答秒數、流暢性、提示層級、用到提示比例、顯示答案比例、兩種間隔天數）× 列 × 欄（25 種分組，2026-10-20 加「選項注音」「報讀提示」），2 個篩選、日期、只算每個字第一次作答、排序、筆數提醒門檻、長條圖／折線圖、存成我的比較、匯出結果＋原始紀錄。目前一次一個指標。
- 圖表顏色依資料視覺化規範：一條線用第 1 色，多組用固定順序 8 色（已用色盲檢查工具驗證，淺色組靠表格與標籤輔助）；格線是實線細線，只有時期分隔用虛線（單一受試研究的慣例）。
- 自動化測試用已知答案的假資料逐項比對（21 項全部通過），包含進階分析與從原始紀錄直接算的結果一致。

### 進階分析（研究用，平常收起來）

給有研究需求的老師做交叉比對。放在老師專區的「進階分析」分頁，一般老師不會看到。做法是「樞紐分析表」（像 Excel 的樞紐分析：選要比什麼、依什麼分組，系統算出每一格的數字）。

| 設定 | 可以選 |
|---|---|
| 指標（一次一個或多個） | 錯誤率、反應時間（第一次作答／答對秒數）、流暢性、間隔、常錯字排序、高字頻生字錯誤率、錯誤類型分布、提示層級 |
| 列（第 1 個分組） | 字、學生、時期、課別、評量目標（題目類型）、評量方式（正確率／流暢性）、選項數或版面（呈現方法）、作答模式（大螢幕／紙筆）、提示方法、答錯規則、主題、正式或練習、日期（週／月） |
| 欄（第 2 個分組，選填） | 同上 |
| 篩選 | 上面所有欄位都能篩，另加日期區間、只看第一次作答 |

- 每一格同時顯示**筆數**；筆數太少（預設少於 5 筆）的格子變淡並提示「資料太少，僅供參考」。
- 可切換成長條圖或折線圖；結果與篩選後的原始紀錄都能匯出 Excel，方便用 SPSS 等軟體再分析。
- 常用的設定可以存成「我的比較」，下次直接開。
- 紀錄要補記的欄位：答錯規則、提示方法（目前只記用到的提示，要另記「當時設定」）、版面（第 0 階段一併加）。

### A8 名詞與時期定義（2026-10-21 草案，討論中）
完整內容在規格書「階段 A 討論資料 → A8」。重點：
- **為什麼**：系統把三套名詞混在一起。每課自動判斷的「時期」是基線期、教學中、教學後、維持期，研究名詞和教學用語混用，而且其實是在判斷「這課教過沒」；學扶卡片又把前測、後測硬套成時期。名詞會寫進每一筆紀錄，之後的一般／進階／研究三種檢視（C1）都要用。
- **文獻查證**：前測／後測是老師日常用語，也是「單組前後測設計」（前實驗設計，只比兩個時間點）。單一受試研究依「有沒有在介入」分基線期（A）、介入期（B，也稱處理期）、維持期，每期要多筆資料（WWC 至少 3 筆、5 筆以上完全符合）；介入結束當節的後測是介入期的最後一筆。RTI 用篩選、進展監控。維護者的理解經查證正確。
- **三個概念**：課程進度（教學前／中／後）、評量用途（平常／前測／後測）、研究時期（基線期／介入期／維持期，研究者事先定）。
- **資料三層、單向相容**：練習 → 一般評量 → 研究評量。研究資料可以併進一般統計（基線期→教學前／前測；介入期→教學中；介入期最後一次→後測；維持期→教學後（追蹤）），一般資料不能被當成研究時期。
- **名詞對照總表**（規格書 A8「名詞對照總表：一般模式 ↔ 研究模式」）：表 1 研究時期與探試類型併進一般統計時算成什麼（基線期的初始探試、介入前補測、未教層的例行探試→教學前／前測；介入期→教學中；介入期最後一次→後測；維持期→教學後（追蹤）；類化探試→另列、不併進正確率主線）；表 2 哪些資料可以進一般統計、哪些可以進研究分析；表 3 分析名詞的一般說法和研究說法。換算要寫成程式裡的一張對照表，三種畫面共用。注意：「學會」的精熟標準還沒統一（研究方法規格書寫連續 3 次 90%，簡報草案寫連續兩次 80%）。
- **程式原則（草案）**：紀錄存事實（正式或練習、用途、日期、教完第幾天；研究另存計畫代號和當時時期），名稱在顯示時才決定；研究資料要在作答前標好；舊紀錄照原樣保留、顯示時換算。
- **和 `docs/research-method-spec.md` 的關係**：那份的主設計「跨行為多探試」是每一課各自依教學日期分基線、介入、維持；系統現在「每課依教學日期自動判斷時期」本質上對應這個設計，只是名稱混用。要算研究資料，還需要教學日期在介入前就記好、條件固定、每期筆數夠。A8 定案後兩份文件的用詞要一起對齊（那份也用「後測」）。
- **待討論**：研究計畫多細、研究時期是「依每課教學日期推算」還是「另建研究計畫指定」（或兩者並存）、前後測的單位（一課或一段學扶課程）、期中檢測叫什麼、能不能事後把舊資料標成基線期（原則上不行）、三種畫面誰看得到、對應表的兩處調整。
- **決定方式：中間路線**（2026-10-21 維護者同意）：分清楚「很難改的」（存進資料的東西：紀錄記哪些事實、教學日期怎麼存、研究資料怎麼標記）和「很容易改的」（畫面上的名詞、圖表、研究設計範本、分析指標）。現在一次定好：一般和進階模式的名詞與畫面；研究模式只定地基（紀錄存事實、教學日期可每位學生各自設定、研究資料作答前就標好、單向相容、研究計畫開始收資料後鎖定、改只能開新版本）；所有名稱集中在一張對照表。研究模式的內容（研究畫面用詞、預設研究設計、分析指標、研究計畫畫面）之後再補，規格書對照總表的研究欄標成「暫定」。
- **研究模式的架構準備**（2026-10-21 檢查現有程式）：沒有「以後做不到」的地方（研究設計範本、層用課次或字組、研究計畫存檔分享、舊資料不會被誤當研究資料、當時的條件都查得到）。要先處理的三件事：

- **教學日期的修改：修正錯誤 vs 計畫變更**（2026-10-21 維護者提出）：改日期不會多出一筆作答紀錄。但只存「作答當下的日期」的話，修正打錯的日期後舊紀錄會前後不一致，所以分兩種：「修正錯誤」（例如 10/5 打成 10/15）連舊紀錄一起套用；「計畫變更」（真的延後開始）舊紀錄維持原樣。做法：教學日期有自己的修改紀錄（哪天改、從什麼改成什麼、哪一種）；改日期時問老師是哪一種；作答紀錄存當時用的教學日期版本。一般、進階畫面用修正後的日期；研究畫面鎖定後仍可修正，但修改紀錄要顯示出來，計畫變更則開新版本的研究計畫。

### 血量模式（3-3b，2026-10-20 維護者定案）
- **只在練習**（正式評量提早結束會讓資料不完整）。
- **幾顆愛心**：開始前在設定裡選（例如 3、5、7 顆）。
- **答錯扣一顆**；**連續答對 3 題補一顆**（不超過一開始的顆數）。
- **愛心用完就直接結束**，看成績。這一次算「做完」，紀錄列入練習的統計，不算中途結束。
- **貼紙**：一樣抽一張（不看剩幾顆）。
- **多人輪流**：個人模式＝每人各自的愛心，某人用完就換下一位繼續、他的部分結束；合作模式＝全組共用愛心，用完全組一起結束。
- **實作細節（2026-10-20 完成）**：
  - 選主題畫面多一列「愛心：不用／3 顆／5 顆／7 顆」，只在練習的正確率模式出現（流暢性、正式評量沒有），這台電腦記住上次的選擇（`settings.practiceHearts`，預設不用）。全課賓果卡也可以用。
  - **一題第一次選錯才扣一顆，同一題再錯不會再扣**（Claude 的設計：照答錯規則一題可能錯好幾次，每次都扣對還在學的學生太嚴格；也和「第一次就答對率」的算法一致）。
  - 「連續答對」指連續幾題第一次就答對；答錯會重新算。
  - 作答畫面上方一排愛心，少一顆時碎掉、補一顆時跳出來。用完時顯示「○○的愛心用完了！」1.6 秒，個人模式寫「換下一位繼續」。
  - 紀錄多 `hpMax`（開始幾顆）、`hp`（這題做完剩幾顆）；Excel 有「愛心（開始時）」「愛心（這題後剩下）」，進階分析可依「血量模式」分組。愛心用完的那次不算中途結束。
  - 打怪獸時愛心用完：不會打敗怪獸，直接到結果畫面，貼紙一樣一張（戰利品照常揭曉）。
- **之後的增強方式（再討論）**：轉蛋、抽獎、轉盤等，**剩幾顆愛心就抽幾次**（例如剩 5 顆抽 5 次）。這是依表現給獎勵，只用在練習；正式評量維持「做完一次抽一張、不看對錯」。

## 3-4. 備課分析（2026-10-20 新增）

給老師備課用：選課本（可多本，例如同年級）、勾課次或存好的段考範圍，統計範圍內常見部件，作為集中識字（部件識字、基本字帶字）的教學重點參考。

- 範圍：課本可複選；課次可勾選；字的種類（習寫＋認讀／只習寫／只認讀）。常用範圍存在瀏覽器 localStorage（`prep-ranges`），畫面狀態存在 `prep-ui`。
- 分析方式：第一層部件（字直接拆開）或拆到最細（部件再往下拆）；預設隱藏單一筆畫；可設定「至少出現在幾個字」。
- 結果：三個重點數字＋三個分頁。部件排行列出出現字數、出現率、範圍內的字、**學過的舊字**（同版本、比範圍更早的課，用來新舊字串聯）；生字一覽列出每字部件與語詞；字頻分頁在 `FREQ`（字 → 排名）存在時才有內容。目前分頁可匯出 Excel。
- 部件來源（備課分析、識字評量的部件提示都一樣）：先用 `lessons.js` 的 `PARTS`（人工），沒有再用 `shared/parts.js` 的 `PARTS_AUTO`（cjkvi-ids 自動拆解，GPLv2，優先台灣字形；罕用部件再往下拆成常見部件；相容表意字轉回一般字；無法編碼的部分略去）。
- 已知限制：自動拆解是「字形結構」，不一定等於教學用部件，例如「王」拆成一＋土、「只」拆成口＋八。發現錯誤可直接改 `shared/parts.js`，或在 `lessons.js` 的 `PARTS` 加人工拆法（優先採用）。重新產生 `parts.js` 會覆蓋手改內容，所以人工修正建議寫在 `PARTS`。

  - 現在：`play.js` 的 `makeOptions` 每題放 1 個同詞易混字，再從干擾字清單**隨機抽**同音、形近字，不夠用同一課的字補；清單依課本版本存（`CONF_ED`）。
  - 問題：323 個字出現在兩本以上課本，其中 126 個在不同版本的干擾字不同（例：「力」翰林二上是「功動」、康軒二上是「刀」）；1,806 字中 1,219 字的干擾字超過 3 個，每次正式評量的組合可能不同；53 個干擾字是罕用字（字頻 4,000 名以後或不在表上）。
  - 理論：干擾字是「字」的特性（形似、音似、同詞），不是出版社的特性；重複測量要每次難度相當；干擾字要是學生認得的常用字。
  - 建議：正式評量每個字固定一組干擾字（字層級、不跟改版、老師確認後定版加版本號，只打亂位置；4 選 1＝同音、形近、同詞各 1，限常用字）；練習可繼續隨機；改了要升版本並記錄。紀錄已存全部選項和錯誤類型，舊資料不受影響；改的時候紀錄加「干擾字表版本」欄，和 A8 的紀錄格式第 3 版一起做。
- **干擾字怎麼分配：不同選項數**（2026-10-21 文獻整理，屬 A3，要和夥伴討論；詳細在規格書 A3「⑦ 干擾字怎麼分配」）：
  - 現在：同詞字一定先放，再同音、形近輪流，不夠用課文字或任何字補。用全部 1,729 個生字跑一次：3 個選項時只有 34% 的題有形近字（三分之二放同音）；4 個選項時 99% 有形近、14% 有補位字；6 個選項時 34% 有補位字；約三分之一的字沒有同音字。
  - 文獻：3 個選項在多數情況夠用，4 改 3 信度不降（Rodriguez 2005 統合分析；特教系學生的研究也一樣）；給身心障礙學生刪掉最弱的干擾項可行（Rodriguez 等 2014）；中文識字困難的學童主要錯在形近字（Woo 與 Hoosain；Cheah 等），同音、形近、同詞混合的鑑別度最好（Liu 等 2018）。
  - 和現在的差異：混合三類和文獻一致；但 3 個選項時形近字最少、補位字多半沒人會選、各字的同音字數量不一樣讓錯誤類型不好比。
  - 草案：3 個＝1 形近＋1 同音（沒有同音放同詞）；4 個＝形近、同音、同詞各 1（缺的補形近）；6 個只在練習、不夠就少放不硬補；部件重組改成形近優先（見下一點的待辦 ⑥）。待討論：正式評量 3 或 4 個（一課 10 字時猜中率 33% 對 25%）、減選項能不能當個別調整。
- **形音都像的干擾字，與沒有同音字時怎麼補**（2026-10-21 維護者提問，屬 A3，待討論；詳細在規格書 A3「⑧」）：
  - 形音都像：同音表 15% 的字和目標字有共同部件、形近表 17% 的字同音或同音節、23 題同一字兩表都有；現在「從哪張表拿就標哪類」，會少算另一類。建議分成同詞、音近、形近、形音皆近四類（規則算＋人工確認，存在固定干擾字表）；選字優先用「純」的；統計時形音皆近自己一欄。紀錄已存 `options` 和 `firstPick`，舊紀錄可以重新分類。
  - 沒有同音字的 574 題：維護者提議用「唸法相同、最常用的字」補。文獻支持同音替代是最常見的錯字（深圳、香港、聽寫研究），但「最高頻的那個」沒有直接實驗證據。資料上可行：已有同音表的題 79% 本來就含最高頻同音字；補字順序＝學過的生字 → 字頻門檻內 → 同音節不同聲調（標音近）→ 都沒有就多放形近或少一個選項，約九成以上補得到。注意破音字（539 題）要用題目語詞裡的唸法並人工確認、干擾字放進語詞不能也說得通、要是小學生認得的字。

  - 部件重組現況（2026-10-21 檢查，和維護者要的「形近優先」不一樣）：`play.js` 的 `makePartsOptions` 把形近字限制在干擾字的一半（無條件進位），其餘先放「和題目字有任何共同部件」的字（從全部生字隨機挑，只共用「口」「亻」也算），最後才放剩下的形近字。形近字還有剩、卻被同部件字佔掉的題：3 個選項 1,206 題（70%）、4 個選項 704 題（41%）、6 個選項 345 題（20%）。要改成：先放完形近字，不夠才用同部件字（共用非部首部件、而且位置相同），再不夠就少一個選項；`optType` 已先判斷形近，不用改。屬 A3。
  - 形近字和同部件字的關係（2026-10-21 維護者同意）：形近字分兩種——「同部件形近」（共用聲旁等主要部件且位置相同，如清晴、柱桂）和「筆畫形近」（只差一兩筆、拆不出共同部件，如己已巳、未末）；只共用部首（如呼和品都有口）不算形近。程式現在的「同部件」＝共用任何一個部件，把同部件形近和只共用部首混在一起。錯誤類型可以在形近底下再記「同部件」或「筆畫」，和 A8 紀錄格式第 3 版、四類分類一起討論。
