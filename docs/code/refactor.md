# 整理程式（重構）的規則與進度

不整個重寫，做功能時順手整理，照這份的規則；整理完更新第 2 節的進度。
檔案之間的關係先看程式地圖 `docs/code/architecture.md`。（2026-10-23 維護者決定）

## 1. 規則

不整個重寫，**做功能時順手整理那次會碰到的地方**，照下面的規則。Claude 不會記得上次整理到哪裡，所以規則和進度都寫在這裡；任何人、任何一次對話接手，都照同一份做。

1. **存資料一律走入口**（為了階段 F 換成線上資料庫時，只要改入口）：
   - 識字評量的設定類資料：用 `data.js` 的 `load(名稱, 預設值)`、`store(名稱, 值)`。
   - 作答紀錄：只能用 `records.js` 的 `saveRecord`、`updateRecord`、`removeRecords`；其他檔案只讀 `records`。
   - 貼紙、頭像：只能用 `window.Rewards`。
   - 備課分析：用 `prep.js` 自己的 `load`、`save`。
   - **只有上面四個檔案可以直接碰 `localStorage`、`indexedDB`**，其他檔案直接用，自動檢查會報**錯誤**（紅叉）。新工具要存資料，先在這裡加一個入口，再改 `check.js` 的 `STORAGE_ENTRY`。
   - 新的儲存名稱（例如 `literacy-xxx`）要寫進 `architecture.md` 第 6 節的表，並想好要不要用 `addBackupPart` 加進備份檔；沒寫進表，自動檢查會提醒。
2. **新的共用程式包成一個盒子**：像 `window.Themes`、`window.Rewards` 一樣，檔案裡的東西只從一個名稱對外提供，避免和別的檔案撞名。舊檔案不用特地改。
3. **整理和新功能分開**：整理用的 PR 不加新功能、不改畫面和行為，PR 說明寫「整理，行為不變」；整理完維護者照平常操作玩一次，確認沒有變。
4. **一次整理一件事**：一個 PR 只整理一個檔案或一件事，壞了容易找原因，也可以用 GitHub 的 Revert（退回）按鈕整個退回。
5. **不改作答紀錄的格式**：整理時紀錄的欄位和意思都不能變；要變就照 `docs/design/records.md` 先討論。
6. **每個檔案開頭和每一節保留中文說明**（現有寫法），整理後說明要跟著改。
7. 整理完在第 2 節把那一項標 ✅、寫日期和 PR；發現新的該整理的地方，加進第 2 節。
8. **後面的選擇不能悄悄改掉前面選好的東西**（2026-10-23 維護者要求）：設定流程是第 1 步 → 第 4 步，作答中也不能因為換課、換題就改變一開始決定的版面或條件。真的要連動時（例如換成正式評量、平板選項要停用），畫面上要看得出來被改了什麼。新功能、修 bug 時都照這條檢查；已知的問題見第 3 節。

## 3. 設定流程與作答畫面的待修問題（2026-10-23 維護者回報，還沒改）

1. **生字賓果選了好幾課，作答中版面會跳來跳去**（維護者實測；**2026-10-26 已修**：`bingoBoard` 改成每位學生整次作答只有一張卡，由她所有課要考的字一起排；字不夠填滿時的補法仍是現狀「所有課本隨機」，等 `pending.md` 決定）：
   - 原因（Claude 2026-10-23 查程式確認）：`play.js` 的 `bingoBoard` 每一課各做一張賓果卡（以「學生｜課次」為單位），題目又是幾課混在一起輪流出，所以每換一課就換一張卡；每課考的字數不同（「只考有教的字」只勾幾個字的課），卡的格數也不同（`gridFor`），版面就跳。
   - 要改成：選完課次、決定好要考的字之後，**整次作答只用一張固定的賓果卡**（所有課要考的字一起排），中間不再換。
   - **字不夠填滿賓果卡時怎麼辦**：現在是從所有課本隨機抓字補，補進來的字可能學生沒學過。要決定補法，見 `pending.md`。
2. **全面檢查設定流程**（2026-10-26 已檢查完，結果和待修問題見 `setup-flow-audit.md`）：照第 1 節規則 8，把「後面的選擇影響前面」的地方列出來逐一處理。已知會連動的：換快速開始卡片會改作答方式（平板 → 大螢幕，有畫面提示）、打怪獸會把「不用主題」改回要選主題（`setup.js` 的主題選擇）、換課次會改題數。下次動到 `setup.js` 時先做這份清單。
