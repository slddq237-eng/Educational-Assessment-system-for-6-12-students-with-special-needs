# 設定流程全面檢查（2026-10-26，B8 的另一半）

照 `refactor.md` 第 1 節規則 8（後面的選擇不能悄悄改掉前面選好的東西）檢查識字評量的設定流程：列出每兩個選項之間的限制，看每一條是「變灰並寫原因」「自動改選並提醒」還是「悄悄改掉」。**只讀程式和實際試跑，這次沒有改程式**；改法在最後一節，等維護者決定再做。

## 怎麼檢查的
- 讀 `data.js`（`playWhy`、`team`、`current`）、`setup.js`（`step3Miss`、`answerList`、`render`、`quizPlan`、`renderThemePick`）、`collect.js`（`willFight`）、`play.js`（`bingoOK`、`gameFor`、`heartsAllowed`）。
- 用瀏覽器（Playwright）直接設定 `state` 後呼叫 `startSession()`，試 216 種組合：評量目標（3、4-1、1）× 玩法（一般、遊戲、賓果）× 作答方式（大螢幕輪流、分區輪流）× 學生數（1、2 位）× 個人或合作 × 練習或正式評量 × 正確率或流暢性。
  - 結果：**沒有程式錯誤，每一種組合的第一題都能作答**（答案選項在畫面上）。
  - 其中 75 種組合「選的玩法不能用、實際改用別的玩法」，設定畫面都有寫原因（見下表）。
- **沒測到的**：這個試跑是直接設定 `state`，沒有真的點設定畫面，所以「按鈕有沒有變灰、原因文字顯示得對不對」是讀程式推的，沒有實際看畫面。

## 發現的問題（照要不要處理排序）

**2026-10-26 更新：下面 5 個問題都已在 PR #159 修好**（賓果題數照實際、其餘四項被改掉時畫面上方寫一行說明）；表裡對應的列已標 ✅。

1. **#17 賓果題數和畫面不一致**（我 2026-10-26 修 B8 時帶出來的，優先處理）：多課賓果時，畫面寫的題數、預估時間比實際多。老師會以為考很多題，結果少了。
2. **#12 換成遊戲時悄悄清掉主題**：學生剛點的主題不見了，卻沒有說。
3. **#14 換快速開始卡片時悄悄重設題數**：老師輸入的題數被改回預設。
4. **#4 只剩 1 位學生時悄悄把分區輪流改回輪流**：老師沒看到被改。
5. **#16 練習和正式評量字數不同**：不算錯，但老師可能不知道為什麼切換後題數變了。

## 建議的做法（等維護者決定）

- **先修 #17**：賓果時 `quizPlan` 也套用「每人最多 36 題、同字只算一次」，畫面和估時照實際數字，旁邊加一句「賓果卡最多 36 格」。範圍小、不動作答紀錄。
- **#12、#14、#4**：改成「被改掉時畫面上寫一行小字」（規則 8 本來就要求：真的要連動時，要看得出來被改了什麼），不用改限制本身。
- **#16**：在題數旁加一句字組說明即可，可以和 #17 一起做。
- **長期**：把表裡的限制集中成一張規則表放在 `data.js`（延伸 B9 的玩法相容表），畫面和 `check.js` 都讀它，之後加玩法或作答方式只要加一列。目前限制散在 `playWhy`、`teamFixed`、`step3Miss`、`renderThemePick` 等 5 個地方，這次是靠讀程式才找齊的。
- **分區輪流支援賓果**：不在這次範圍。限制 4×4 以內、等比例縮小是我的建議，要不要做、字多時怎麼辦等維護者決定，見 `pending.md`、`roadmap.md` E14。
