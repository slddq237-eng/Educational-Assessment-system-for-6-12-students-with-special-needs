### 平台首頁規劃（2026-10-20 維護者提出，對應 3-5）
目標是之後成為中型網站：老師可以依細節分類，找到要拿來教學、評量或備課的工具。現在工具還不多，先把架構做好，之後加工具只要加一筆資料。
- **工具清單資料化**：每個工具一筆資料（名稱、網址、說明、用途〔教學／評量／備課〕、領域〔識字、之後的數學等〕、適用年級、狀態、標籤），放在共用檔案（例如 `shared/catalog.js`）；首頁依這份清單自動產生卡片。
- **找工具的方式**：上方搜尋框＋分類篩選＋「最近用過」。
- **分類（2026-10-20 維護者確認）**：用途（教學／評量／備課）、課程（國語、社會技巧……）、主題（國語：識字、閱讀……；數學之後再補）、適用年級。「適合個人或小組」「需不需要投影」「學生自己用或老師用」之後看需要再加。
- **回首頁按鈕**：每個工具每一頁固定位置都有「回首頁」。識字評量的作答畫面為了避免學生誤觸，不放回首頁，要先按「結束」；設定、結果、選主題、貼紙簿、老師專區都放。生字賓果已加上「回平台首頁」（2026-10-20 維護者要求；賓果原本的「回首頁」是回到賓果第一頁，保留不動）。

### 多人合作破關遊戲（3-7，2026-10-20 維護者提出，之後再做）
參考 Kahoot 合作模式、Blooket：大家輪流答題，一起破關。
- **累積型**：答對累積技能條，集滿（或時間到）就攻擊怪獸；逃跑遊戲累積逃跑速度；賽車遊戲累積加速。
- **分階段**：例如每答對 3 題進入一個小遊戲，玩完再回來答題。
- 原則：只在練習；小遊戲和動畫只出現在題目之間，不影響反應秒數的計算；每人每題仍各記一筆。
- 開工前要討論：先做哪一種（攻擊怪獸、逃跑、賽車）、小遊戲要玩多久、有沒有時間限制、和打怪獸（3-3）共用哪些圖。
- **貼紙夥伴打怪獸**（2026-10-24 維護者決定；原本提的「學生用自己的貼紙角色互相對戰」改成合作，避免程度弱的學生一直輸、為了搶快亂猜、稀有貼紙越強越不公平）：
  - 角色：開始前學生從自己的貼紙簿挑一張當「這次的夥伴」；還沒有貼紙的學生用預設角色。
  - 出場：照打怪獸的節奏每 3 題過場一次（`settings.sceneEvery`），進度條跑完後接一個「貼紙對上怪獸」的畫面；動畫只在題目之間，不影響反應秒數。
  - 攻擊力：只看這幾題第一次就答對的題數，不看速度、不看貼紙稀有度（所有貼紙一樣強）；可以有不同的攻擊特效，只是外觀不同。
  - 答錯：呈現「沒打中、休息一下」，不出現被打倒的畫面。
  - 獎勵：照打怪獸現在的規則，全組得到同一張戰利品貼紙，每次評量剛好一張。
  - 只有一個人作答也能用：自己的角色單獨打怪獸。
  - 做法：當作「打怪獸」的加強，加一個「貼紙夥伴出場」開關，不新增玩法卡片，作答紀錄格式不用改。
  - 固定只在練習，正式評量不能用。
  - 圖：用現有貼紙做「跳起來、衝過去」的動作，不重畫每隻的動作。
  - 時程：階段 E（E5），等 B9 相容表做好、照表加一列再做。
  - 還要決定的兩件事記在 `pending.md`「相關小組討論」。

### 大螢幕分區輪流（E14）
（2026-10-24 維護者提出）
- **想法**：大螢幕輪流作答時，所有學生（2～4 位）的版面同時顯示在畫面上；輪到的人那一區亮起來作答，其他人的區暗掉、選項遮住。
- **決定**（2026-10-24 維護者）：**新增一種輪流模式**，不改原本的全螢幕輪流。不改原本模式的原因：輪流也用在正式評量，改版面等於改正式評量的呈現條件（屬 A3）；同一位學生前後資料一半全螢幕、一半分區，分析時分不出差異是學會了還是版面造成的。
- **為什麼值得做**：一次只有一人作答，所以沒有「大螢幕・同時」（設定畫面的「準備中」選項）的兩個難題：只唸一題不會混音、不需要多點觸控（舊型電子白板也能用）。分區版面做好後，以後做「同時」模式可以沿用。
- **好處**：等待的學生看得到自己的區和進度、比較不會分心離開；賓果每人一張盤面（程式已經是每人各一張）可以一直留在畫面上；作答還是一次一題，計分和紀錄邏輯不用大改，主要改畫面排版。
- **要注意**：每區變小，對視力弱、手部動作不精準的學生不利（輪到的區放大、其他區縮小可以減輕）；畫面元素多，容易分心的學生可能受干擾；換人過場（大頭像＋「換 ○○」）要改成「亮起那一區＋提示音」之類；合作打怪獸的怪獸放哪裡（中間共用一隻，或每區一隻）要再決定。
- **做法**：
  1. 先做 B9 玩法相容表，「分區輪流」在表裡加一列，標出可搭配的玩法、主題。
  2. 設定畫面的作答方式多一個選項（或在輪流下加「版面：全螢幕／分區」），先只開放練習。
  3. 到學校大螢幕實測：字夠不夠大、學生會不會分心。
  4. 穩定後再評估要不要往「大螢幕・同時」發展。
- **還要決定**：正式評量要不要開放（屬 A3）；如果開放或想在分析分辨，作答紀錄要不要加欄位記「全螢幕／分區」（改紀錄格式，先討論，只加新欄）。只開放練習時可以先不記。

### 社會技巧互動故事（D8）
（2026-10-25 維護者提出；起因：參考夥伴做的社會技巧影片簡報教材，改成網頁做）
- **想法**：不做真的影片，做成類似簡報的互動故事。人物圖只有微微晃動，說話時跳出對話框、播放配音；一段時間後跳出選項，學生選了走不同劇情，最後依結局給引導式的建議。
- **參考網址**（2026-10-25 維護者提供）：互動式影片的範例 https://www.youtube.com/watch?v=qGN_HZA7ckE （只當參考、放連結，不下載或轉存影片內容）
- **可行性**：技術上不難，純網頁就能做（人物晃動用 CSS 動畫、配音用音檔或瀏覽器語音、分支用一份劇本資料記「選 A 到哪一幕」）。播放程式寫一次，之後每個故事只是一份新劇本。**主要的工在內容**：劇本、人物圖、配音。
- **好處**：檔案比影片小很多，可以放 repo、學校網路跑得動；改台詞只要改文字；學生要做選擇、比被動看影片投入，選錯可以回頭重選、比較不同做法的結果；平板可用。
- **要注意**：
  1. 分支越多內容越多：每個故事 2～3 個選擇點，分支最後回到主線。
  2. 情境、選項、建議要懂特教的老師設計；選錯的結局要溫和引導，不像處罰。
  3. 人物圖、聲音要確認授權（自己畫、AI 產生、或可免費使用的素材，加進 `data-sources.md`、`about.html`）；配音用老師的聲音，不用學生的聲音、照片（repo 公開）。
  4. iPad 不能自動播放聲音，要先按「開始」。
  5. 學生識字量不一：台詞、選項都要有聲音，選項最好配圖示。
  6. 要不要記錄學生的選擇：記了老師可分析，但是新的作答紀錄，先討論；第一版建議不記。
  7. 影片檔不放 repo（單檔上限 100MB）；真的需要影片就放 YouTube（不公開）再嵌入。
- **建議做法**：新增工具屬「下一個工具做什麼」（①全體決定），目前優先是階段 A、B，先不正式開工。可先做小樣品（1 個故事、4～5 幕、1 個選擇點）在會議展示，再決定。要做時開新資料夾（例如 `tools/social-story/`），不動識字評量；首頁卡片等 D1 工具清單。
- **還要決定**：要不要做、誰負責、第一個故事的主題、圖和配音從哪來、要不要記錄學生的選擇。
