# 簡化合作流程：請夥伴選（2026-11-02 提案，① 級，還沒決定）

**目的**：每個 PR 要更新的文件太多，同一件事記在好幾處，兩位維護者都累。下面 5 個項目，每項有「現在怎麼做」「選項」「建議」，**夥伴只要選字母**。全部選完後，才會開一個 PR 一次改完（所以現在這份只是提案，不會改任何規則）。

**怎麼回答**：在這個 PR 留言，例如「1B 2A 3B 4C 5A」，有想法再補一句。不確定就寫「問」，我會用白話再解釋。
**六個考量**（挑選時都要顧到）：新人快速上手、合作效率、維護者現在的效率、AI 運行效率、結構清晰、日後工程師接手。

## 項目 1：發 PR 前「改完要更新哪些檔案」

**現在**：`docs/rules.md` 有 12 列表格，每種改動要更新不同的檔案。
| 選項 | 內容 |
|---|---|
| A 不變 | 維持 12 列 |
| B 縮成 3 條 | ① 改作答紀錄格式或正式評量條件 → 先討論，寫決策紀錄、更新 `records.md`；② 新增程式檔或儲存名稱 → 更新 `architecture.md`（自動檢查會提醒）；③ 其他都只要 PR 標題和說明 |
| **C 縮成 4 條（建議）** | 同 B，另加④：**新的外部資料或存學生資料的功能 → 更新 `data-sources.md`、`about.html`、`privacy.html`** |

**建議 C 的原因**：B 把授權、個資兩類刪掉，但這兩類出錯是法律問題，而且 `check.js` 目前不會自動提醒（只有「對外連線」會）。

## 項目 2：路線圖打勾與首頁「最後更新」

**現在**：每個新功能的 PR 都要把 `roadmap.md` 那一列改成 ✅，並更新首頁 `index.html` 的「最後更新」。
**要先知道**：`index.html` 是共用檔案，改它的 PR 一定要擁有者審核，所以**每個新功能 PR 都被迫等擁有者**。
| 選項 | 內容 |
|---|---|
| A 不變 | 每個新功能都改 |
| **B 建議** | `roadmap.md` 只在「整個階段」或「一個編號項目」完成時打 ✅（目前就是這樣，把它寫明）；首頁「最後更新」改成維護者**覺得老師需要知道時**手動更新，不再是每個功能 PR 的必做項 |
| C 更少 | 同 B，另外 `roadmap.md` 完全不打勾，狀態改看 PR 標題和決策紀錄 |

## 項目 3：規格書（claude.ai 文件）

**現在**：定案後，要請擁有者回規格書那一節標「已定案，見 GitHub `docs/○○.md`」。
| 選項 | 內容 |
|---|---|
| A 不變 | 每個定案都回去標 |
| **B 建議** | 規格書只用來討論，定案後**不用回去標**。規格書開頭本來就寫了「最新決定以 GitHub `docs/` 為準」（`rules.md`「規格書的角色」），夠了 |

## 項目 4：哪些修改要擁有者審核（`.github/CODEOWNERS`）

**現在**：整個 `docs/`、`shared/`、`tools/literacy/`、首頁、`README.md`、`CLAUDE.md`、`.github/` 都要擁有者審核，連改一個錯字也是。
| 選項 | 要審核的路徑 |
|---|---|
| A 不變 | 現在全部 |
| B 縮小 | `shared/`（教材資料）、`tools/literacy/`、`privacy.html`、`about.html`、`.github/`、`CLAUDE.md`、`docs/design/records.md`；**一般文件小修不用審** |
| **C 建議** | B 再加 `docs/decisions/`（決策紀錄）、`docs/plans/a3-conditions.md`、`docs/design/a8-terms.md`：這幾份寫的是 A3、A8，改錯會影響作答紀錄和正式評量 |

**注意**：改 `.github/CODEOWNERS` 本身就要擁有者同意；改完後夥伴改一般文件不用等，但**少了一層看過**，所以 C 把最重要的幾份留下。

## 項目 5：精簡文件時「原文搬到 history」的舊規則

**現在**：`CLAUDE.md` 和 `docs/INDEX.md`「寫文件的規則」仍寫「精簡、重整文件時拿掉的內容原文搬到 history 檔案」，和 2026-11-02 的新做法（決定的理由記進 `docs/decisions/`）並存。
| 選項 | 內容 |
|---|---|
| A 不變 | 兩套並存 |
| **B 建議** | 改成：**涉及「決定」的內容 → 寫決策紀錄；純粹重複或過期的文字 → 可以直接刪（git 留得住）；`docs/history/` 保持原樣當存檔，不再新增** |
| C 全面停用 history | 同 B，另外把 `history/` 的舊檔搬進 `decisions/`（工程很大，不建議） |

**注意**：這項會改 `CLAUDE.md`，是維護者 2026-10-24 的決定（「精簡文件不直接刪」），改它要維護者同意。

## 如果全選建議（1C 2B 3B 4C 5B），我會改哪些檔案

`docs/rules.md`（表格縮短）、`CLAUDE.md`（一句）、`docs/INDEX.md`（寫文件的規則）、`docs/plans/roadmap.md`（寫明打勾時機）、`.github/CODEOWNERS`（縮小）、`docs/rules.md`「規格書的角色」。**不改任何網頁和程式**。預估一個 PR，因為動到 `.github/` 和 `CLAUDE.md`，仍是 ① 級，要擁有者同意。
