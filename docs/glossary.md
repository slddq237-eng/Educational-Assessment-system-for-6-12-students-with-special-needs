## 四、評量與紀錄的名詞

| 名詞 | 白話 |
|---|---|
| 正式評量 | 條件固定的評量（完全不提示、不回饋對錯、不報讀），結果納入分析；不玩遊戲 |
| 練習 | 條件可以自由調整，可以玩遊戲、拿貼紙，結果另外統計 |
| 前測／後測 | 老師作答前按的標記，專區畫面直接寫這兩個詞 |
| 基線期／介入期／維持期 | 單一受試研究的三個時期，由研究者在研究計畫事先設好 |
| 單一受試研究 | 針對一位或少數學生，反覆觀察、比較介入前後的研究方法（見 `docs/design/research-method-spec.md`） |
| 跨行為多探試 | 研究方法規格書的主設計：每一課各自分基線、介入、維持 |
| 學扶 | 學習扶助。舊文件的「學扶前後測」卡片，已合併進「正式評量」卡片；平台之後應該不會再出現這個名詞 |
| 紀錄第 3 版 | 作答紀錄的欄位格式，2026-10-25 升級，改格式前要先討論 |
| 資料三層 | 練習 → 一般評量 → 研究評量，單向相容：研究資料可併進一般統計，反過來不行 |
| 代號 | 學生在平台上的名字，不能用真實姓名 |

## 五、平台與技術名詞

| 名詞 | 白話 |
|---|---|
| 部件三層 | 把一個字拆成零件的三種深度：第一層按結構拆 2～3 塊、第二層可教學角度拆到部首、第三層一路拆到最底層（`docs/design/parts-layers.md`） |
| 干擾字 | 選擇題裡的錯誤選項，分同詞、音近、形近、形音皆近四類 |
| QR code 平板作答 | 平板掃 QR code 開作答頁，做完用 Google 表單送回只含代號的紀錄 |
| localStorage、IndexedDB | 瀏覽器自己的儲存空間。資料只存在老師自己的瀏覽器，要用備份檔搬家 |
| Vercel 預覽 | 每個 PR 自動做出一個可以點開試用的網站，合併前先試 |
| `check.js` | 自動檢查：語法、教材資料、版本號、有沒有學生資料等，GitHub 會在每個 PR 自動跑 |
| PR（Pull Request） | 「請把我改的合併進去」的申請頁，也是看誰正在改什麼的看板 |
| ①②③ 通知等級 | ① 先討論再做、② 做完讓夥伴知道、③ 不用通知（詳見 `docs/rules.md`） |
